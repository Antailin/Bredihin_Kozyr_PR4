### Приложение включает.

- **Страница 1 (Page1)**: Расчёт функции \( v = \frac{1 + \sin^2(x + y)}{|x - \frac{2y}{1 + x^2 y^2}|} \cdot x^{|y|} + \cos^2(\arctan \frac{1}{z}) \).
- **Страница 2 (Page2)**: Расчёт условной функции \( c \) в зависимости от сравнения \( x \) и \( y \), с выбором варианта \( f(x) \) (sinh(x), x² или e^x).
- **Страница 3 (Page3)**: Табличный расчёт функции \( y = 0.1 a x^3 \tan(a - b x) \) в заданном диапазоне с шагом, вывод результатов и построение графика.

Приложение использует навигацию между страницами через Frame в главном окне, обрабатывает ошибки ввода (например, деление на ноль, недопустимые значения).

### Технологии

- **Язык программирования**: C#.
- **Фреймворк**: .NET Framework 4.7.2 (на основе App.config).
- **UI-фреймворк**: Windows Presentation Foundation (WPF).
- **IDE**: Visual Studio (рекомендуется для сборки и запуска).
- **Библиотеки**: Стандартные библиотеки .NET для математики (System.Math), графики (System.Windows.Media) и интерфейса (System.Windows.Controls).
- **Дополнительно**: Используются изображения формул (PNG-файлы в папке Images), которые отображаются в интерфейсе.

### Архитектура приложения

- **Главное окно (MainWindow)**: Содержит StackPanel с кнопками для навигации между страницами и Frame (MainFrame) для отображения страниц. 
- **Страницы**:
  - Каждая страница — это отдельная страница, наследующая от Page.
  - XAML-файлы определяют разметку интерфейса (Grid, StackPanel, TextBox, Button, Canvas для графиков, Image для формул).
  - Code-behind обрабатывает события (кнопки "Вычислить" и "Очистить"), валидацию ввода и расчёты.
- **Графика**: На Page3 используется Canvas для рисования графика (Polyline для кривой, Line для осей и сетки, TextBlock для меток, Rectangle для рамки).
- **Обработка ошибок**: Функции TryParse для проверки ввода с использованием CultureInfo.InvariantCulture, проверка на NaN/Infinity, специальные случаи (деление на ноль, cos(y)=0 для tg(y), x<0 с нецелым |y|).
- **Приложение (App)**: Стандартный класс Application с StartupUri на MainWindow.xaml. Нет дополнительных ресурсов или логики.
- **Локализация**: Интерфейс на русском языке, использование CultureInfo.InvariantCulture для числовых форматов.
- **Структура проекта**:
  - **pages**: Namespace для страниц (Page1.xaml/Page1.xaml.cs, Page2.xaml/Page2.xaml.cs, Page3.xaml/Page3.xaml.cs).
  - **Images**: Папка с изображениями формул (formula1.png, formula2.png, formula3.png).
  - **MainWindow.xaml/MainWindow.xaml.cs**: Главное окно с навигацией.
  - **App.xaml/App.xaml.cs**: Точка входа приложения.
  - **App.config**: Конфигурация runtime (.NET Framework 4.7.2).

#### Тренировочный тест — TestMethod1

Тест TestMethod1 демонстрирует работу основных методов объекта Assert:

| Метод | Назначение |
|---|---|
| Assert.AreEqual(expected, actual) | Проверяет, что два значения равны |
| Assert.AreNotEqual(notExpected, actual) | Проверяет, что два значения различны |
| Assert.IsTrue(condition) | Проверяет, что условие истинно |
| Assert.IsFalse(condition) | Проверяет, что условие ложно |
| Assert.IsNull(obj) | Проверяет, что объект равен null |
| Assert.IsNotNull(obj) | Проверяет, что объект не равен null |

> Тест пройден успешно — все утверждения корректны и выполняются без исключений.

### Причины успешного выполнения тестов:

1. Корректная бизнес-логика. Математические функции правильно реализуют формулы из варианта №3. Граничные случаи (деление на ноль, нечётные показатели при отрицательном основании, неопределённость тангенса) обрабатываются через исключения или возврат NaN, что соответствует ожиданиям тестов.

2. Изолируемость кода. После рефакторинга математическая логика вынесена в MathFunctions — статический класс без зависимостей от UI. Это позволяет вызывать методы напрямую без инициализации WPF-окна, что является ключевым условием unit-тестирования.

3. Полнота покрытия ветвей (метод «белого ящика»). Тесты охватывают все ветви условных операторов: if/else if/else в ComputePage2, проверки на ноль и граничные значения в ComputePage1 и ComputePage3.

4. Правильное использование `[ExpectedException]`. Тесты, ожидающие исключение, декорированы атрибутом [ExpectedException(typeof(ArgumentException))], поэтому MSTest засчитывает выброс исключения как успех, а не ошибку.
